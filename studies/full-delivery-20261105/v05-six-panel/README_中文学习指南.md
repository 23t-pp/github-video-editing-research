## 1. 先把这几个名词弄懂

- **帧**：一张画面。24fps 表示每秒24张，2帧约0.083秒。
- **轨道**：时间线中的一层。上面的视频可以盖住下面的视频。
- **裁切**：只显示画面的某一块。此处是矩形窗口，不是识别人脸或人物的AI抠像。
- **关键帧**：记录某个时刻的数值。例如第0帧透明度0，第2帧透明度1，软件负责算中间的变化。
- **源入点**：从原素材的哪一帧开始播放；它与片段在总时间线上的开始位置不同。
- **渲染**：把图层、关键帧、裁切和声音算成可以播放的成片。

这次效果的核心很简单：**同一个视频播放六份，每份只露出不同区域；六个窗口按顺序显现。** 六份视频的播放时间始终一致，才能把脸、车窗和方向盘接成完整画面。

## 2. 实际选了哪些素材

原文件是 `D:/速度与激情/11 速度与激情10（2023）4K.mp4`，约12.6GB，3840×1600，23.976fps，HEVC 10bit，HDR PQ / BT.2020，原声是EAC3 5.1。

|镜头|原片起点|准备的长度|在小样中承担什么|
|---|---|---|---|
|A：迎面驶来的汽车|01:57:29.800（7049.8秒）|2.25秒|背景，建立车辆运动方向|
|B：驾驶员特写及后续追逐镜头|01:57:49.400（7069.4秒）|3.75秒|六格的共同内容，接着变成全画幅|

先做了较稀疏的全片抽样，再检查高速追逐段的密集抽帧。选择这两段的理由是：A有向观众逼近的运动，B给出驾驶员的表情与操控，卡片过渡有内容上的衔接。B后面的航拍与车内切换是这段原片本身已有的剪辑，不能算作本次新做的转场。

转换时把HDR亮度映射到普通屏幕使用的SDR Rec.709；保留整个2.4:1电影画面，缩到1920×800后上下各补140像素黑边。这样没有把人物横向拉宽，也没有为了填满16:9强行裁掉两侧。黑边是本次构图选择。

完整截取与颜色转换参数保存在 [media-source-ledger.json](hyperframes/assets/media-source-ledger.json)。工程只携带几秒短片，不需要复制整部电影才能打开。

## 3. 按时间线拆开看

以下帧号从0开始。区间右端不包含在片段内，例如30–48表示30到47帧。

|全局帧|时间|操作|
|---|---|---|
|0–29|0–1.208秒|只显示A底图|
|30|1.250秒|左上格开始淡入|
|32|1.333秒|左下格开始淡入|
|34|1.417秒|中上格开始淡入|
|36|1.500秒|中下格开始淡入|
|38|1.583秒|右上格开始淡入|
|40|1.667秒|右下格开始淡入|
|43–47|1.792–1.958秒|全部格子已完成短距离滑入，拼成完整B画面|
|48|2.000秒|接到完整B镜头，源入点是B第18帧|
|102–107|4.250–4.458秒|最后6帧淡出|
|108|4.500秒|视频时间线结束|

每格用2帧从透明变为不透明，用3帧完成很短的垂直滑动。整体卡片组缩放到画布的72%。HyperFrames使用 `power3.out` 做滑入减速；OpenChatCut教学版使用其原生 `easeOut` 关键帧表达同类动作，两者不是逐像素相同的缓动曲线。

编号示意：

```text
0 左上 | 1 中上 | 2 右上
3 左下 | 4 中下 | 5 右下

出现顺序：0 → 3 → 1 → 4 → 2 → 5
```

注意：**六段B的时间线起点都是30帧，源入点都是0。** 出现顺序由透明度关键帧控制。如果把第六段B的源视频也晚启动10帧，六格里的动作会不同步。

第48帧为什么从B第18帧接起？因为B已经在格子里播放了 `48−30=18` 帧。继续播放第18帧才能让动作往前走；如果又从0播放，人物会突然重复动作。

## 4. HyperFrames实际做了什么

主工程在 `hyperframes/`，最先看两个文件：

- [sample-config.json](hyperframes/sample-config.json)：本次的时间、大小、入场顺序等参数。
- [build.mjs](hyperframes/build.mjs)：根据参数生成网页动画和一次混音。

`index.html` 是可以在Studio打开的视频工程，里面有底图、六个裁切窗口、后段完整镜头和一条音轨。每个窗口都是640×540，窗口里面仍放完整1920×1080画面，然后用位置偏移选择相应的区域。六个窗口都以同一个B视频、同一个播放起点驱动。

例如中上格看画面的中间三分之一：

```text
窗口位置：x = 640，y = 0
窗口大小：640 × 540
窗口内完整视频的位置：x = -640，y = 0
窗口外的内容：隐藏
```

`gsap.timeline({paused:true})` 是动画时间表。暂停不是“不播放”，而是把时间交给HyperFrames控制；渲染某一帧时，引擎会跳到对应的精确时间。

### 为什么还有一个 .render-source 文件夹

本机实测出现FFmpeg直接写文件 `Permission denied`，但它输出到管道、由可用的Node保存文件能成功。没有修改系统安全设置或全局安装。

因此本次使用的真实流程是：

```text
原电影 → 两段SDR短片
             ↓
build.mjs → 可编辑的视频HTML + 自动生成的逐帧图片HTML
                                  ↓
                      HyperFrames官方渲染108张PNG
                                  ↓
                      FFmpeg编码画面＋混音到stdout
                                  ↓
                         Node保存最终MP4
```

逐帧图片HTML仍由HyperFrames计算六格的动画、裁切与合成；不是把一张静态图做成视频，也不是FFmpeg单独拼出卡片。实际渲染记录见 [渲染记录.json](evidence/渲染记录.json)。108张完整输出帧共约113MiB，渲染约40秒。

### 在PowerShell中重做一次

打开PowerShell，先进入工程目录：

```powershell
Set-Location 'D:\gpt\2026-11-04\ps-c-windows-system32-winget-install-2\outputs\v05-six-panel\hyperframes'
$nodeExe = 'C:\Users\PC\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe'
```

`Set-Location` 是切换当前文件夹。`$nodeExe` 是保存本次已验证可正常写文件的Node程序路径。这里使用它，是因为这台电脑PATH中的另一份Node曾出现写入问题。

```powershell
& $nodeExe .\build.mjs
```

`&` 的作用是运行变量里存的程序。`build.mjs` 读取参数、准备逐帧素材、生成动画工程和混音。

```powershell
& $nodeExe .\hf.mjs check . --at '0,1.5,1.875,2.1,4.3' --timeout 45s
& $nodeExe .\hf.mjs check .render-source --at '0,1.5,1.875,2.1,4.3' --timeout 45s
```

`check` 会检查代码与真实浏览器中的运行情况；`--at` 指定要检查的秒数。`hf.mjs` 是启动官方HyperFrames CLI的小包装，只给当前子进程指定已安装的Chrome、FFmpeg和ffprobe路径。

```powershell
& $nodeExe .\hf.mjs preview . --background --no-open --no-proxy --port 5210
```

`preview` 打开Studio服务；`--background` 让服务持续运行；端口5210对应本机预览地址。也可以运行 [Open-Preview.ps1](hyperframes/Open-Preview.ps1)。

实际渲染的命令形状如下；路径可自行换到你的工作文件夹：

```powershell
$framesDir = 'D:\gpt\2026-11-04\ps-c-windows-system32-winget-install-2\work\v05-sample\hf-rendered-frames'
& $nodeExe .\hf.mjs render .render-source --fps 24 --format png-sequence --workers 1 --low-memory-mode --sdr --experimental-fast-capture=false --no-best-effort --output $framesDir
& $nodeExe .\encode.mjs $framesDir '..\V05六格卡片_成片.mp4'
```

- `--fps 24`：每秒24帧。
- `--format png-sequence`：输出HyperFrames真正合成后的PNG画面。
- `--workers 1`：只启用一个渲染工作进程，便于排查问题。
- `--sdr`：输出普通动态范围。
- `--no-best-effort`：遇到实质渲染问题时让任务失败，不拿缺帧结果充数。
- `encode.mjs`：先检查108张序列图是否连续，再编码并用ffprobe核对输出。

想按当前参数完整重渲染，可运行 [Render-Sample.ps1](hyperframes/Render-Sample.ps1)。它会生成一个新的中间帧目录，保留PNG方便检查，约需113MiB磁盘空间。脚本不改执行策略；如果本机不允许运行ps1，可直接逐条运行上面的命令。

这些脚本的工具路径是针对你当前电脑配置的。迁移到别的电脑时，需要安装相应版本并改脚本中的Node、HyperFrames、Chrome和FFmpeg路径。

## 5. OpenChatCut里怎样学、怎样改

首页点击“导入工程”，选择 `.ccproj`，看到“素材4/4”后再打开。这个包已在本机通过真实UI导入为新副本，并检查到两条序列。

### 序列01：OCC原生六格教学

包含7条视频轨和1条音频轨，共9个片段：

- 底轨放A的0–48帧，以及B的48–108帧。
- 上方6轨各放一份B，全部位于30–48帧。
- 六格每段都有自己的裁切、透明度与垂直位置关键帧。
- 8个视频片段全部静音；Master音轨只播放一次。

可以先把播放头停在约1.58秒，点击其中一个格子的片段，再打开“属性”。查看“基础”里的裁切和变换，以及“动画”中的关键帧。用隐藏轨道的眼睛按钮，逐个观察哪个区域消失，是理解图层最直观的办法。

OpenChatCut工具输入的裁切单位是像素，保存的工程Doc内部使用比例。其位置关键帧使用画布百分比，关键帧时间使用**片段局部帧**。例如“中上格全局34帧开始出现”，对于从全局30帧开始的片段，就是局部第4帧。不要把全局34直接写成局部34。

### 序列02：HF成片整合

这里有一段刚渲染的HF成片，长度108帧，音量1。它用于继续接镜头、添加音乐或字幕。**这一段MP4内部的六格已合成，不能在这条序列里直接拆出原来的HTML图层。** 要改每格，用序列01，或者修改HF源码后重新渲染并导入。

OpenChatCut工程与HyperFrames工程没有自动双向同步。修改其中一个，不会自动修改另一个。这次交付的两个版本是同一结构的两种可编辑实现。

### 本次CLI到底执行了什么

不是向聊天模型发一句话后假定它完成了，而是调用了OpenChatCut的官方外部Agent命令：

```text
project new                         创建1920×1080、24fps的新项目
tools call import_assets --apply    导入两段短片、Master和HF成片
tools call edit_track --apply       创建六格视频轨和音频轨
tools call edit_item --apply        添加片段、裁切和关键帧
tools call manage_timelines --apply 创建HF整合序列
project show --doc --json           把实际保存的Doc读回来检查
```

`--apply` 表示把该工具的编辑实际写入工程。`project new` 本身就会创建工程，不需要这个参数。CLI回执和应用HTTP读取的工程数据已比对一致。

可移植包通过项目源码中的官方 `buildProjectExport()` 生成，格式是 `openchatcut-project@2`；媒体嵌在包里。`原生工程Doc.json` 只是阅读结构的快照，不能替代包含素材的 `.ccproj`。

## 6. 声音如何处理

这次保留A/B原片声音并交接混合，所有画面窗口本身静音。另用数学合成了六个短促轻敲音，对应六次入场。没有调用云端音乐生成，没有使用外部BGM，也没有把它宣称为完成了原参考配乐的BPM逆向。

最终AAC是48kHz单声道；Master来自原片下混与轻敲音。峰值约 **−7.80dBFS**，没有达到0dBFS。视频精确108帧、4.500秒；AAC编码尾部填充使MP4容器显示约4.521秒，属于音频封装余量，不是增加了一帧动画。

18秒慢放文件刻意无声，用于看动作，不用于判断正常速度的听感。

## 8. 建议按这个顺序练习

|难度|练习|你会学到什么|
|---|---|---|
|1 / 5|在学习播放器里逐帧看30–48帧|时间、帧率、出场顺序|
|2 / 5|在OCC里逐个隐藏六条轨道，再恢复|图层覆盖与矩形裁切|
|2 / 5|把HF参数 `gridScale` 从0.72改成0.65，重渲染|整体尺寸与构图|
|3 / 5|把 `order` 改成 `[0,1,2,3,4,5]`|同一效果因出场顺序产生不同节奏|
|3 / 5|调整透明度关键帧，让出现更硬或更柔|淡入长度与节奏感|
|4 / 5|换成另外两段同规格素材，同时保持六格和全画幅源时间衔接|素材准备、时间连续性、声音交接|
|5 / 5|增加人物抠像跨格、跟踪、变速与强节拍配乐|这是下一阶段复合效果，当前小样未包含|

初学先只改一个参数。HF当前是固定1920×1080、24fps、3×2结构，`columns/rows/width/height` 是本次规格记录，不是已经实现的任意网格布局生成器。不要只改这些数字就期待自动生成九宫格。

参数修改后的推荐顺序是：保存 `sample-config.json` → 运行 `build.mjs` → `check` → Studio预览 → 渲染。`build.mjs` 会重新生成 `index.html`，因此如果直接在Studio或HTML里手改动画，先备份这些修改；重新build不会自动保留所有手工编辑。初学阶段以参数文件为修改入口最容易复现。
