# 《弯心 / APEX》OpenChatCut 可编辑工程

交付规格为 1920×1080、24fps、1440 帧，即 60 秒。项目采用独立镜头、独立声音轨和原生文字/裁切图层。在 OpenChatCut 项目首页使用“导入工程”打开同目录的 `弯心 APEX · 速度与激情一分钟混剪.ccproj`；包内携带48份媒体，不需要原片盘符。工程包已通过官方导入函数恢复为独立项目，结构与全部媒体哈希回验通过。

## 怎么改

默认激活的 `01 HF精确特效` 时间线保留42个逐镜片段及两根声音轨，只在片名、三联与结尾三个窗口叠加帧准确的无声HF插片。这三段可独立替换。切换到 `02 原生可编辑` 时间线可直接修改片名文字与三个面板的裁切；它同样具有完整42镜和双声轨。两条序列分别播放，声音不会因为存在两条序列而重复叠加。

- `V1 主画面`：42 个独立电影镜头。拖动片段改变时间；修剪时保留每个素材的入点，素材前后通常各有 12 帧余量。
- `A1 原创配乐` 与 `A2 源片声音`：两根独立立体声混音，均从第 0 帧开始，持续 1440 帧。可分别调音量、静音和修剪。视频片段全部静音，避免重复叠音。
- 原生片名：第 7 帧开始、第 75 帧结束。选中文字可改“弯心”或“APEX”、字号、颜色与字体；关键帧可调入场。
- 三联分栏：第 675–719 帧，三份视频位于独立轨道，可各自换素材、改入点或裁切。中间和右侧分别延迟 5 和 10 帧显现；底色位于独立轨道。
- 最后一镜：第 1418 帧开始淡黑，1439 帧为黑。透明度关键帧可直接调整。

三联面板裁切窗分别为 `(0,140,638,800)`、`(642,140,636,800)`、`(1282,140,638,800)`。42 个底层镜头完整保留，三联效果覆盖窗口内的底画面。

## 原生效果与 HyperFrames 的关系

文字、颜色、时间、窗口位置和面板延迟可在 OpenChatCut 中编辑。原生片名使用短促透明度/位移关键帧，对应 HyperFrames 的斜向遮罩露出；二者入场形状不同。微软雅黑与 Arial 是此本机设计字体，跨电脑打开时应安装对应字体，或在文字检查器更换。普通原生文字没有伪装成可执行的 HyperFrames HTML。

## 验证文件怎么看

`逐镜装配验证.json` 记录每镜的时间线位置、源素材入点及实际素材帧数；`原生特效验证.json` 记录可编辑图层和几何参数。`官方工程包验证.json` 对官方导出包内每份媒体与服务实际字节计算 SHA256；`官方工程包导入回验.json` 记录官方导入函数恢复独立项目后的结构与媒体核对结果。

桌面实际播放、拖动、试听属于另一步检查，读取验证报告中的相应字段。脚本结构和哈希通过不等同于已经人工试听。

## 可复现操作

操作脚本在本次工作区的 `work/fast60/occ`，各次 CLI 命令和返回原文均保存在同目录。脚本限定只改本任务创建的项目 UUID，旧工程不参与装配。

1. `preflight.mjs`：核对运行中服务、CLI 使用同一 isolated-dev 资料库，并创建新项目与分轨；已装配后不应再次运行空项目预检。
2. `assemble.mjs`：读取锁定的 `hyperframes/edit.json`，检查实际媒体帧数、规格、完整 1440 帧边界及双声轨；同名素材以 SHA256 检查更新，不能只依赖名字。本次修订11镜后，先由 `refresh-staged-pool.mjs` 调用官方草稿命令和保存函数，移除未使用的旧版池条目，再导入最终字节。当前 CLI 没有公开 `manage_media_pool`，该回退走受限进程内后端；已有备份与审计。
3. `native-effects.mjs`：通过官方 CLI 建立原生文字、三个视频裁切面板与末尾透明度关键帧。
4. `export.mjs`：在 OpenChatCut 仓库目录通过 Node 24 与仓库现有 `tsx` 加载器运行，调用官方 `buildProjectExport()`。不自行编码工程格式。
5. `import-package.mjs`：通过官方 `importProjectPackage()` 的 `publish` 主机扩展接口恢复为新项目，发布过程调用官方 `createProject` 和服务端 `rotateAgentSession`，随后由官方导入器恢复运行记录。进程内资料库桥接只允许写本次新副本，普通读写委托官方 `getStoredEntry/setStoredEntry`，运行记录委托官方 `writeAgentRuntime`。

`hf-companion.mjs` 在原生版完成后通过官方复制序列命令建立01版，只更换效果层。`时间线核验.json` 的 `shots` 数组从真实01序列读取，字段为 `id/startFrame/frames/assetStartFrame`，并逐字段与设计文件比对，可用于最终影片封装验收。

本机 Node 24 的 Blob 流可能一次产生整根17MB音轨，使官方记录超过16MB单行上限。导出脚本仅将媒体 Blob 的流分成64KB块，格式编码仍由未修改的官方 `buildProjectExport()` 完成；包已实际通过官方解析与导入。

`最终工程验证.json` 是最终数据验收，初始空工程的准备快照已移回工作目录。桌面实际视听验收请结合主流程的界面检查记录。

实际桌面验收已完成：01精确版29.29秒显示正确三联并播放推进到44.41秒；02原生版右侧面板已真实拖动并撤销，恢复原始构图；两根WAV均加载完成且持续60秒。主流程没有进行扬声器人工试听，此项在报告中保留未测。界面操作证据见同项目 `evidence/本机播放器与编辑器核验.json` 和三联屏截图。

本次官方导入还实际遇到并处理了两个主机差异：上传请求必须带同源 Origin；会话 generation 由服务端管理，不能用普通键值写入。本次通过受限本机请求头适配和官方 `rotateAgentSession` 处理，未修改 OpenChatCut 源码。失败的临时导入副本已通过官方删除函数清理，最终仅保留制作项目和成功恢复副本。

桌面检查中首次预载曾显示棋盘；预载后02原生版29.29秒已实际看到三联，右窗有可拖动选择框，两根WAV均完成加载。OpenChatCut 的预览视频使用 WebCodecs 画布，DOM 中没有 `<video>` 不代表视频缺失。详见 `预览排查记录.json`，其中界面观察由主流程操作者提供。
