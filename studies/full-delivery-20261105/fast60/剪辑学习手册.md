# 《弯心 / APEX》一分钟混剪

先播放同目录的 **弯心_APEX_60秒.mp4**。第二遍可以双击 **学习播放器.html**，点右边的段落，或用“上一帧”“下一帧”看一个剪点两侧各是什么画面。下方会显示镜号、源文件和原片入点。这个页面和成片放在同一个文件夹里就能使用。

## 先用三个片段练眼睛

**3.75–7.50 秒，看因果。** 先看手指打开开关，再看氮气瓶、转速表，最后才给车群出发的全景。三个特写交代了“怎么发动”，所以全景出现时观众看得懂结果。把转速表从时间线临时移到车群之后，重新播放一次，你能感受到这个小动作怎样改变顺序感。

**28.125–30.00 秒，看三张脸。** 左窗沿用上一镜布莱恩的正脸，中窗选另一位驾驶员的反应，右窗是一位女性驾驶员。三块画面依次相隔5帧入场，构图分别对准脸部。第30秒三联同时结束，配乐强拍和破烟而出的黑车一起回来。练习时先把三窗同时放出，再恢复5帧错位，比较眼睛先看向哪里。

**52.50–60.00 秒，看一次收手。** 爆炸之后切成夕阳下的对视和人物交接，最后一镜从56.25秒开始一直看到两辆车驶向分岔。单镜停留3.75秒，恰好是开场两个短特写总长度的四倍以上。这里一直保持128 BPM，减速感来自镜头变长、鼓和低音陆续退出。

## 一分钟怎么分配

| 成片时间 | 我在画面里做了什么 | 可以跟着试的剪法 |
|---|---|---|
| 0–7.5 秒 | 夜场车聚、起跑线、开关、气瓶、仪表、车辆出发 | 先交代空间，再用连续动作切近景。片名留在左下，车身仍然可见 |
| 7.5–22.5 秒 | 漂移、贴车追拍、换挡、擦过施工架、车队驶过 | 两部不同电影也能接。先比较运动方向、物体大小和速度，再选切点 |
| 22.5–30 秒 | 车库、静车和人脸，把注意力从速度转向驾驶者 | 音乐变稀时拉长观察时间，给一次多窗动效留足阅读时间 |
| 30–52.5 秒 | 黑车冲出烟尘，车身落地。接车轮、冰水，再进入直升机追车 | 车轮圆形把两处外景接起来。后半用远景交代危险，用眼神和孩子的反应交代人物，再回远景看结果 |
| 52.5–60 秒 | 对视、交接、两车分道、淡黑 | 把最后一个八拍给同一个航拍。淡黑只占最后22帧 |

42指可单独拖动的主画面片段。部分片段含电影原有的机位变化。例如S32从直升机切到司机，S40保留两位驾驶者的对视。想追查自己看到的某一帧，打开镜头表，先找时间线位置，再找源片入点。

## 两个工程怎么选

### 我想用鼠标改片

1. 打开本机 OpenChatCut，在项目首页选择导入工程，选 **openchatcut** 目录里的 `.ccproj`。这个包携带实际用到的媒体。解包后也可以在本机已经建好的工程里直接学习。
2. 打开名称以 **01** 开头的时间线，先看准确的成片版。底轨拆成42个镜头，另有三个 HyperFrames 效果插片。若修改了被插片覆盖的底层画面，需要在 HyperFrames 中同步更换并重渲染该插片。
3. 切到 **02** 时间线，选中文字可改“弯心”或“APEX”，选三联屏任意一条视频轨可以调裁切和位置。这里的片名用 OpenChatCut 原生关键帧重做，进场轮廓和01有细微差别。
4. 单独静音 **A2 源片声音**，听配乐怎样带动剪点。再打开A2、静音 **A1 原创配乐**，听轮胎、发动机和撞击怎样交代动作。两条一起播放时，音量从1开始。
5. 第一次试剪可只移动S04与S05之间的剪点1帧，再撤销。每个源片段前后各带12帧余量，换算成24fps各是半秒。想移动整段较长镜头时，可重新从原电影选取并替换。

重启电脑后，用下面两行在 PowerShell 启动桌面上已经装好的 OpenChatCut。保持这个窗口打开，再访问 `http://127.0.0.1:5199/`。第一行进入项目文件夹，第二行运行本机启动脚本。

```powershell
cd "$env:USERPROFILE\Desktop\OpenChatCut-main"
.\Start-OpenChatCut.ps1
```

### 我想改动效，或复现导出过程

解压 **HyperFrames可编辑工程.zip**。进入 **hyperframes**，双击 **Preview.cmd** 可在本机开启工程预览。主要文件如下。

| 文件 | 用途 |
|---|---|
| `edit.json` | 42个主镜头、素材在时间线里的位置、音乐路径、片名和三联参数 |
| `镜头表.csv` | 用Excel或文本编辑器查镜号、用途、原片入点、使用多少帧。它是阅读表，程序读取edit.json |
| `style.css` | 片名字体、大小、颜色、位置，三联窗口与间隙 |
| `composition.py` | 生成可预览的HyperFrames HTML。片名的上移、三窗的显现、片尾的淡黑都在这里 |
| `assets/shots` | 带修剪余量的静音镜头。P03是三联右窗的额外素材 |
| `assets/cues` | 从对应镜头抽出的30个原声片段。原电影混音中的部分配乐和人声可能一并保留 |
| `assets/audio` | 独立配乐、剪辑用的两条混音分轨及总声master.wav |
| `../music` | 原创乐曲的MIDI、四条乐器分轨、拍表、作曲脚本、混音脚本与测量结果 |

以下命令在 **hyperframes** 目录的 PowerShell 窗口执行。本机使用已安装的解释器和工具。换电脑时可在 `Render.cmd`、`hf.mjs` 或对应环境变量中指定 Node、Python、FFmpeg 与 HyperFrames CLI 路径。

```powershell
$py = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
$nodeExe = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe"
& $py -X utf8 composition.py
& $nodeExe hf.mjs check . --at "0.9,12.2,29.4,43.8,58.6" --timeout 60s
& $nodeExe hf.mjs preview . --background --port 5213 --no-open
& $py -X utf8 tools/render.py
```

第一行和第二行把程序的位置记进两个变量。`&` 表示“执行这个路径的程序”。`composition.py` 将可编辑参数生成为 `index.html`。`check` 在多个时间点打开工程并检查。`preview` 启动本地预览。`render.py` 用真正的 HyperFrames 渲染片头68帧、三联45帧、淡黑22帧。其余帧直接读取各镜头在时间线使用的范围，最后以 FFmpeg 编成一条 H.264 视频和一条 AAC 立体声。重新执行时，输入完全相同的效果区间会复用缓存。

**改片名的小练习。** 在 `edit.json` 的 `effects.title.text` 写入两个新字，在 `style.css` 调整 `.word` 的字号，重新运行上面的生成和渲染命令。默认的新成片写在工程文件夹的上一级。`Render.cmd` 可以直接完成这次生成与渲染。

若在 Studio 里直接改画布，可使用 Studio 自带的 Export。手册里的渲染命令读取参数文件，每次重新生成 HTML；检测到手动修改时，会先将现有 HTML 另存为 `index-studio-*.html`，方便找回。

**换取景的小练习。** 改镜头入点时，同一镜号请同步更新 `edit.json` 的 `assets` 和 `shots` 两处 `sourceIn`。例如只重取S05，仍在 **hyperframes** 目录执行下面三句。第二句重新构建两条声轨和总声，避免画面已经移动而原声留在旧位置。

```powershell
& $py -X utf8 tools/prepare_media.py --sources "D:\速度与激情" --only S05
& $py -X utf8 ../music/build_final_mix.py
& $py -X utf8 tools/render.py
```

## 为什么30秒落在第720帧

成片每秒24帧，帧号从0开始，所以第720帧从30.000秒起显示。128 BPM表示每分钟128拍，一拍约0.46875秒，即11.25帧。一拍并非整数帧，实际剪辑按**累计拍点**四舍五入。这样连续四拍正好45帧，整片128拍刚好1440帧。开关、氮气、转速、发车的起点分别是第90、113、124、135帧，可以在学习播放器里对照。

配乐以D小调的两小节旋律作为反复出现的线索。音高和鼓密度逐步增加，第30秒回到完整鼓组，最后减去鼓和低音。声音以48,000 Hz记录，24fps的每个画面帧对应2,000个音频采样。两条PCM分轨在音量1时相加，逐采样等于总声。

## 片源与颜色

使用了目录中编号02–11的十部电影，其中S01取自《东京漂移》，S23取自《速度与激情7》，S31–S39取自《速度与激情10》，最后三个镜头回到《速度与激情7》。镜头表中的编号对应原文件名的前两位，编号09是《特别行动》，编号10才是《速度与激情9》。

`ffprobe` 读取实际视频流参数。编号02的文件名写着60帧，流记录的平均帧率为24000/1001，约23.976fps。编号11同为约23.976fps且为PQ HDR，其余输入里还有60和120fps。本片选定24fps作为统一交付帧率。取材时保留原动作时长，按源时间取样；HDR镜头先映射到SDR，再和其他镜头统一为Rec.709。电影活动画面为1920×800，上下各140像素黑边，放在1920×1080画布内。

## 可以看到的验收材料

- **成片验证.json** 记录视频流、音频流、总时长、实际解码帧数和文件指纹。
- **evidence/成片分镜.jpg** 展示18个来自最后MP4的画面，**evidence/成片抽检.json** 记录42个片段中点和编码前参考图的比对，以及6处AAC与总声的同步检查。
- **openchatcut** 下的核验文件记录真实时间线上的剪点和官方工程包导入后的媒体恢复情况。
- **evidence/双工程重建对照.json** 记录从 OpenChatCut 的01时间线读回42个镜头位置、配合 HyperFrames 的135个效果帧重新编码的结果。它与交付MP4的文件指纹完全相同。
- **music/FINAL-MIX.md** 说明原声如何铺进时间线，哪些地方降低音量，怎样检查两轨相加。
