# 10条参考视频：本地音频节奏与强起音分析

本轮实际执行了FFmpeg本地解码、HyperFrames 0.8.216信号分析与montage 0.4.1基线比较。**没有实际监听音轨、没有上传、没有装模型。** 以下BPM、起音、音色分段均为机器测量候选；不冒充曲名识别、听觉确认或成片复刻。

音量大不等于节拍：RMS只描述电平；谱通量检测“频谱突然发生的新变化”，可能是鼓点，也可能是对白辅音、whoosh、碰撞或引擎声；DP跟拍才是对起音序列施加周期模型。三层数据在JSON里分开。

## 方法与实际执行记录

1. 从manifest.local.json按ID读取原MP4；每条带源SHA256。FFmpeg仅解码第一音轨为22050Hz/单声道/16bit PCM，写入本目录VXX.mono.wav，不修改原视频。
2. 本机FFmpeg直接写工作目录曾返回Permission denied。已改用`-f wav pipe:1`返回二进制，由可写的Codex Node runtime保存Buffer；最终10条均exit 0。此修正不改系统权限。
3. 直接导入本机HyperFrames 0.8.216的signal provider和频带分析库：谱通量起音、40–240BPM自相关/DP、4秒最短音色结构。直接调用signal provider，未进入可上传的best/API provider。
4. 自写脚本复用HF频带，去局部均值后列自相关峰；8秒滑窗/4秒步长交叉检查。候选峰包括长节奏型及倍半速，不自动认定全部为曲速。
5. montage基线使用log-RMS正差，覆盖能量起伏；其结果和谱法不一致时明确保留冲突。
6. `scene-candidates.json`来自320×180/阈值>0.10的未清洗变化候选。这里只提供按视觉分数独立选出的复核例子，不计算“卡点命中率”，不把闪白/动作误报当cut。

可复跑（以下均使用本机已存在工具，参数说明在脚本中）：

```powershell
$audioNode = "C:\Users\PC\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe"
& $audioNode .\work\reference-reverse\audio\analyze-audio.mjs
& $audioNode .\work\reference-reverse\audio\summarize-audio.mjs
```

`analyze-audio.mjs`会从原MP4重新生成音频与JSON；`summarize-audio.mjs`增加中文判断和视觉复核点。操作参数、退出码和源路径仅在本地operations.local.json；每条JSON保留工具源文件hash。VXX.json的beats与onsets分开，onsets是检测到的频谱起音候选，beats含周期模型插入/平滑的推断。

AAC解码出的音频长度与容器视频长度可能相差几十毫秒，本轮V01/V02/V05/V08/V09均如此。此处所有时间从解码音频0秒计，原素材未加偏移；用于逐帧复刻时应结合音视频PTS、播放器试听与30/25/24fps帧边界检查，不能把毫秒小数当真实感知精度。

## 学习顺序（仅指音频骨架，不是整条视觉复刻难度）

先V10（80/160稳定、短片）→V04（124/62清晰，练分段起势）→V08/V01（140稳定，开始区分拍与额外音效）→V02/V03（段落与细分歧义）→V07/V09（拒绝强行出beat，练手工锚点）→V05（多算法冲突）→V06（130秒长片、多段与静音重入，必须分段）。完整难度还取决于视觉遮罩、素材动作衔接、速度曲线与关键帧，不能从BPM单独排行。
