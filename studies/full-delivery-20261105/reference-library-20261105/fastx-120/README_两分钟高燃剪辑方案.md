# 速度与选择｜两分钟高燃剪辑方案

这是能编辑的**73个镜头槽计划**，还没有剪成视频。已实际查看30张候选中心单帧和总览；只读ffprobe确认源片规格，没有回看所有候选的完整动作，也没有锁定源入出点。JSON的source_in/source_out全部为空；表中电影时码是候选中心，**不是可直接导出的入点**。

先抓危险，再让观众认人；第一轮街道追逐后留15秒给人物，再把高速公路/直升机的体量推上去。最后用反应与对讲机留下悬念。它是主题式高燃重组，不是原电影单场追逐复述；跑道、武器和刮擦单帧不能证明逃脱、发射或胜负。

文件：[plan.json](plan.json)保存可改参数与素材目录；[shot-plan.csv](shot-plan.csv)可用Excel改镜头；[节奏设计](music-design.json)、[拍点表](beat-markers.csv)、[可编辑MIDI](128BPM_120秒_可编辑节奏.mid)、[原创节奏导轨](128BPM_120秒_原创节奏导轨.m4a)。修改CSV不会自动写回JSON；批量重建时应同步修改build-plan.mjs中的spec再运行，避免两份计划不一致。

## 交付与节奏

- 交付：24fps，120秒，2880帧；1920×1080，活动画面1920×800，上下各140像素黑边，保留原片2.4:1。
- 源片：3840×1600、24000/1001≈23.976fps、10bit BT.2020/PQ HDR；这些是本机ffprobe实际返回。
- 节奏：128BPM，4/4，64小节、256拍。现有MIDI/音轨是原创节奏导轨，尚不是完整配器/混音的最终歌曲。
- 切点：从累计拍数换算24fps，再取最近整数帧；一拍约11或12帧、两拍约22或23帧、四拍45帧、八拍90帧。不要逐镜时长先四舍五入再累加。最大拍点量化误差约20.833毫秒，所有章节边界恰为整数帧。
- 源23.976与交付24并非完全相同：默认保持源真实时间，常规帧采样而非光流；若选择逐源帧解释为24，会提速0.1%，声音也要同步、入出点要重算。原生分析证据不做改帧率。

## 一拍槽与重复候选怎么处理

S38–S53是16个一拍槽（82.5–90秒）。优先把同一原镜的脚/踏板、手/挡杆、仪表/边缘、控件/手指、脸/方向盘、机身/门内、缆线/车顶、亮火星/刮擦边缘分成互补细节：源时间继续向前，不能每槽从同一动作起点重放。4K源可供适度裁切，但若细节软糊或构图不成立，保持原景别；不能凭中心单帧保证眼部特写有足够分辨率。

重复候选只是“再去这个中心附近查找”，不是批准重播同次换挡/同次碰撞。若找不到不同动作或同镜连续范围，换同职责源镜；也可让一镜跨过几个节拍槽，只用标记保留节奏结构。73个槽不强迫73次实际换画面，更不能用静帧横移凑成动态。

## 学到的手法如何用

- V20动作硬切 / R05动作相位匹配：控制手/脚、方向盘与车辆动作先直接硬切；匹配方向/大小/动作相位。
- V18人物章节：用角色建立、威胁、反应和行动结果分组，避免全程随机车镜头。
- V16/V17记忆窗：人物关系段最多一处矩形回忆窗；不用每个转弯都插卡。
- V19同心形状连接：红控件/仪表/轮毂可试1–2次圆形匹配，普通叠化能成立就不做复杂门户。

不宜直接套用：

- **整片逐帧人物抠像/手指门户**：现有候选不提供动态alpha；精修成本高，也会分散驾驶动作信息。
- **每刀RGB故障/白闪/甩镜**：源镜已有高速、火星、摄影运动；叠满会让路线和车距不可读。
- **参考小窗默认参数直接套73镜头**：背景、主体与方向不同；模板不是自动识别动作/空间的系统。
- **大量光流慢放或轮毂光流**：快旋转、烟雾、遮挡容易变形；默认原速，必要变速单独做短样片。
- **同段10秒音乐或同次碰撞硬循环**：破坏段落推进和动作因果，不能用数量填充时长。

最多保留一套短标题、一处矩形/圆形桥和自己的尾卡。先把车的方向、车距、人物判断剪清楚，再加图层。OCC负责主时间线和基础变换；HF/GSAP只做必要的短合成。复杂alpha、跟踪、曲线变速不是已具备的自动服务。

## HDR转SDR与画幅

1. 先检查HDR原片在正确HDR监看/播放器中的亮度与肤色。

2. 在浮点/足够精度链中把PQ线性化，做tone mapping，再转换Rec.709。

3. 按实际高光和肤色调曝光/高光滚降，保留火星/车灯层次，不把高光全夹成白。

4. 先做日景、夜景、强光各2–3秒样片，统一肤色与黑位，再批量做选定短段代理。

5. 保留3840×1600比例，缩1920×800后上下各140黑边；不把2.4:1拉伸到16:9。

6. 输出标记Rec.709/有限范围，检查没有重复tone map、灰黑、过饱和红与色带。

可试的FFmpeg滤镜起点（仅滤镜文本，不是本轮已渲染的结果）：

```text
zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,tonemap=tonemap=hable:desat=2,zscale=t=bt709:m=bt709:r=tv,format=yuv420p,scale=1920:800:flags=lanczos,pad=1920:1080:0:140:black
```

本机ffmpeg帮助已核实zscale/tonemap和hable/desat；本滤镜链是起始方案，尚未对电影短段实际渲染或视觉验收；npl/峰值与曝光应按素材和监看校准。只给最终选定的短段做代理或转换，不转整部电影。

## 对白、车辆音效与配乐

本方案不假装已选好台词或拥有干净stems。建议四轨：

- **A1 128BPM原创导轨/将来完整配乐**：完整120秒结构，按六段能量分层；当前导轨可用于选镜，不当作最终已混音歌曲。
- **A2 原片对白/呼吸/车内原声**：少量完整语义短句，字幕核对；对白出现时音乐局部降约6–10dB可作试验，具体听辨调整。
- **A3 车辆/刮擦/旋翼/换挡**：源片常混有配乐；没有干净声段时使用已授权独立SFX，不能宣称EQ或取中置声道就能完美去音乐。
- **A4 少量设计冲击/上升与环境**：只服务段落/主落点；16个一拍槽不各叠一次hit，不把没有发射动作的器材静帧配成导弹发射。

1. 先核对实际台词、开始/结束呼吸与语义，不按图片硬字幕拼接虚假对白。

2. 若源是多声道，先确认布局再试中置候选；中置也可能含配乐，非干净对白保证。

3. 轻降噪/EQ/包络只能改善可懂度，不能无损分离重叠音乐。

4. 对白与车辆动作声做短J/L-cut可连续，但不能制造未发生的开枪/命中。

冷开只保留少数真实冲击；52.5–67.5秒减鼓/低频层让人物有呼吸；高潮细节段不每拍叠hit；末段给完整短句/尾音留下空间。试混目标可从-14至-16LUFS-I、True Peak不高于-1dBTP起步，之后按平台和内容调整。这是计划目标，尚未混音测量。

**为什么不把10秒参考曲硬循环两分钟：** 不能把约10秒参考片段机械循环12次当完整两分钟配乐：乐句、和声/人声、段落落点与尾声不完整，重复动机会失去推进；若按128BPM算10秒只有21又1/3拍，也不是完整4/4乐句的整数循环。即使参考实际BPM不同，也需独立分析并取完整乐句。交叉淡化只能藏接缝，不能补出真正的建立/呼吸/高潮/收尾。

## 原片硬字幕与源段复查

当前候选显示原片有烘焙中英字幕，不能承诺可直接关掉；优先另找无字幕版本/源镜无字时段。若只能用当前源，不用大面积上下裁切毁掉2.4:1构图，不假装AI修复已完成；需要清理时逐镜评估。

每个槽锁定前填写：真实源入点/出点、动作方向、接触/反应相位、同镜可用长度、余量、是否已用过、硬字幕、原片声段。需要的源长度要覆盖时间线槽长；变速或转场时另算，不把建议回看窗口整段直接导出。

建议按JSON的operational_order执行：

1. 按候选中心±4秒先看动态，登记真实镜头起止，不把该窗口当可用范围。

2. 每镜足够长再分配sourceIn/sourceOut与首尾余量，重复候选检查非重叠/连续源时间。

3. 先做A/B连接与C一组8–12秒小样，验证方向、HDR→SDR、字幕、音效。

4. 确定120秒节奏后补剩余镜头；一拍槽素材不足可让一镜跨节拍标记，不硬凑73次画面变化。

5. 准备必要mask/标题，再导入OCC或HF工程；plan.json不是OCC原生工程。

6. 选定短段代理或外部合成后才渲染最终120秒，不处理整部电影。
