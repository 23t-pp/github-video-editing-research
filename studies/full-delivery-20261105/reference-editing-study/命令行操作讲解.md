# 这次是怎样分析视频的：命令与证据

命令行是让程序按明确参数工作。你不需要先背完所有参数；先理解输入文件、要执行的操作、输出放在哪里。

本次实际执行记录见[证据与执行记录](证据与执行记录.md)。下面分清“已经运行的流程”和“给你复查时使用的命令”。没有把没执行的制作步骤写成成功结果。

## 1. 确定在操作哪一个文件

```powershell
$videoToStudy = 'C:\Users\PC\Downloads\丝滑BMW_M4剪辑_汽车剪辑_汽车摄影_caredit_BMW.mp4'
Get-Item -LiteralPath $videoToStudy | Select-Object Name, Length
Get-FileHash -LiteralPath $videoToStudy -Algorithm SHA256
```

`$videoToStudy`是保存路径的变量。`-LiteralPath`按原样解释中文文件名。`Length`是字节数。SHA-256可理解为文件指纹：以后文件被替换，即使名字相同，指纹也会变。本次10条都已计算并写进清单。

## 2. 读参数，不重编码

```powershell
& 'C:\Users\PC\Apps\ffmpeg\bin\ffprobe.exe' `
  -v error -show_streams -show_format -of json $videoToStudy
```

`&`让PowerShell执行后面那个路径里的程序；路径加引号是为了正确处理空格。行末反引号表示下一行仍是同一条命令，复制时不要在反引号后加空格。

- `-v error`：只显示错误日志。
- `-show_streams`：看视频/音频轨、分辨率、帧率等。
- `-show_format`：看容器时长、体积等。
- `-of json`：输出结构化文本，方便脚本读取。

这是查询命令，不改写视频。本次发现不同片是24/25/30fps，分辨率也不相同。因此逐帧时不能全部按30fps计算。

## 3. 抽帧为什么分两轮

第一轮是“地图”：每片24格总览；短片每0.5秒一张，V06每1秒一张。它让人快速找到可能的转场位置，却会漏掉1–2帧闪白。

第二轮是“放大镜”：在关键区间提取更多原帧，比如V04眼罩、V07指缝、V10轮毂。V06三个关键切点专门看了相邻24fps原帧，才能判断“硬切还是叠化”。

核心FFmpeg滤镜大致如下，实际脚本见[scripts/source/extract-details.mjs](scripts/source/extract-details.mjs)：

```text
select：只取指定时间区间内的若干源帧
scale：缩到便于并排看的大小，不改变原视频
pad：补齐统一画布
drawtext：写上源时间戳
tile：按行列排成一张联系表
```

本机FFmpeg直接写图片曾出现`Permission denied`。没有因此更改系统权限：改用`-f image2pipe pipe:1`让FFmpeg输出图片字节，再由可写的Node运行时保存文件。视频解码和图片生成仍由FFmpeg完成。这是本次确实使用的流程。

要自己复查一个区间，可以运行本学习包提供的小脚本：

含义：使用已验证可写的Node，查看V10的6.4–8.9秒，输出约每3个源帧一张的联系表与参数JSON到`evidence/V10`。这是复查工具，不会剪掉或覆盖原视频。密帧仍可漏掉两次采样之间的内容；精确判断要看相邻原帧。

## 4. 音乐分析到底做了什么

已经对全部10条执行了以下音频解码逻辑：

```text
ffmpeg -i 输入.mp4 -map 0:a:0 -vn -ac 1 -ar 22050
       -c:a pcm_s16le -f wav pipe:1
```

`-map 0:a:0`选择第一条音轨；`-vn`不处理视频；`-ac 1`转成单声道；`-ar 22050`指定分析采样率；`pcm_s16le`生成16位PCM数据；`pipe:1`交给脚本保存。

之后实际调用本机HyperFrames 0.8.216的信号分析模块，估计起音、节拍、段落变化、近静音；再用独立频谱周期计算和montage能量基线比较。**不是把一个猜测的`hyperframes beats`命令写出来就宣称已经运行。** 实际调用在[scripts/source/audio/analyze-audio.mjs](scripts/source/audio/analyze-audio.mjs)。

本机版本使用打包chunk里的导出函数，这属于版本绑定实现。脚本快照用于理解本次执行；HF升级后内部chunk名称可能变化，不能假设永久可用。声音数据和解释已保存，日常学习无需重跑。

本次没有听辨原曲、识别歌名、验证歌词、做音源分离。具体限制及候选BPM见[音乐卡点说明](音乐卡点说明.md)。

## 5. 为什么还要看OpenChatCut源码

“界面有AI按钮”与“能导出干净的人物透明视频”不是同一个事实。审查源码是为了区分已实现什么、只是布局辅助什么、哪些链路还没测试。

查询用到了`rg`：

```powershell
rg -n 'playbackRate|scaleX|borderRadius' 'C:\Users\PC\Desktop\OpenChatCut-main\src\editor'
```

`rg`是文本搜索，`-n`显示行号。搜索命中是线索，还需要读上下文，不能只看出现了“tracking”就断言有三维追踪。

已经核查的结果：基础变换可关键帧；恒速可调；圆形/矩形mask和部分GL转场可用。MediaPipe粗占用网格、简单位置跟踪和高精度动态rotoscope不等价。具体证据在[工具能力核查](工具能力核查.md)。
