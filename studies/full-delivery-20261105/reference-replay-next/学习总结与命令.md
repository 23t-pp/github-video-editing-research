# 从“剪在一起”到“动作接起来”

本次最值得学的是：**让下一镜的一部分先出现，再让整个场景跟上。** 观众的视线已经跟住手、车轮或车身，背景变化便更容易被接受。参考V07多次使用这种层次关系。

以下记录的是制作依据、实际操作和检查方法，便于你复现；原作者用了什么插件、具体速度曲线和工程参数，不能仅凭成片唯一反推。

## 一、先确定参考和音乐

本次真实随机抽中V07，记录保存在 `随机参考抽选.json`。继续制作时沿用该结果，不因为某一段难做而重新抽。

参考V07自身为25fps，已按原帧率生成751帧图谱。本次审看13页原生图谱，另对86张转场关键帧放大检查；这不等于把751张都按原尺寸单独验收。

音乐直接从已建音乐库取V07的音乐主体候选。这样参考的手势节点和当前音乐仍处于同一时间轴，便于对照。音频起音分析提供辅助位置，低置信度的BPM估计没有被当成严格节拍表。

原音乐30.000181406秒，成片30秒，差0.181406毫秒。这个差小于一帧的0.04秒，来自尾部8个44.1kHz采样帧的最小裁切。保留音乐原速度，按它决定片长。

## 二、每个镜头先确认能用多久

用 `ffprobe` 查看素材参数：

```powershell
& 'C:/Users/PC/Apps/ffmpeg/bin/ffprobe.exe' -v error -show_streams -show_format -of json 'D:/速度与激情/11 速度与激情10（2023）4K.mp4'
```

- `-v error` 只显示错误，减少屏幕杂讯。
- `-show_streams` 看视频帧率、尺寸、音频和色彩。
- `-show_format` 看容器信息。
- `-of json` 输出给脚本可靠读取的结构化数据。

《速度与激情10》是HDR片源，本次先做HDR→SDR色调映射，避免直接压进普通显示后出现灰雾或异常高亮。其余片源按实际色彩读取处理，不能根据文件名里的“4K / 60帧”直接猜参数。

素材截取保留两端各12帧余量，正式使用通常从文件第12帧开始。余量中可能已经包含别的机位，不能直接往两边拉长。

这次实际修了三种问题：

1. 踏板片段在文件F18就切车外，F7–9还有原片烧录字幕。最后只取F10–17这8个干净帧，末帧多保持一次，填满9帧槽；没有生成中间帧。
2. 街角跟拍在F30换机位。使用区间改为F6–29，长度仍为24帧。
3. 原橙车镜头长期被人群挡住。改用《速度与激情2》1610.64秒附近26帧的黄紫双车平行跟拍。

这些修正不会改变音乐长度和后续转场时间。

## 三、手为什么能跨两个场景

以6秒的方向盘接力为例，图层关系是：

```text
上层：B镜头中抠出的真实手 / 前臂，逐帧运动
下层：A镜头的公路车队，继续正常播放

到切换点：下层换成B完整驾驶舱，使用与上层接续的源帧
```

成片F153开始播放B前景，到F161结束；F162接完整B。B素材从文件F12开始，因此完整B从F21继续。这个数字关系是：`12 + (162 - 153) = 21`。若背景重新从F12播放，就会发生动作倒退。

这里用的是逐帧透明PNG。PNG的RGB保留实际素材像素，alpha决定哪里透明。不是把一张静态手图旋转九次：手本身在转方向盘，指节与运动模糊也随真实原帧变化。

边缘制作采用人工轮廓锚点、短距离光流预测和局部GrabCut细化。光流只辅助定位轮廓，没有给整段视频生成补帧。非常模糊或本来没有手的帧，保持透明，比编出一块手形更可靠。

你可以打开 `hyperframes/assets/alpha/B04-gear-hand/alpha-evidence.png`：左边是原画面，中间是棋盘格上的透明前景，右边是黑白遮罩。边缘夹着大块背景、手指被切掉或轮廓突然跳动，都能在这里发现。

## 四、轮胎、飞车和门户如何对应参考

**轮胎擦镜。** 原参考银白扇面会翻转和张开；汽车片中没有这样的物件，便以真实旋转轮胎承担遮挡。轮胎上缘已被原片裁掉，因此限制附加旋转并让裁边留在画外。它复刻的是“先进入旧画面、再接新背景”的结构，不能称为完整扇面形变复刻。

**腾空车接力。** 从两架直升机之间的源片里只抠车身，排除直升机、绳索和天空。7帧前景先出现在旧公路，接着展示同源全景。放大初期会显露原车体只有百余像素宽的局限；透明合成不会凭空恢复细节。

**侧窗门户。** 在真实侧窗内取四个点，人工首中尾锚点约束光流跟踪。新镜头先投影到这四点组成的区域，9帧里逐渐铺满画面；旧车窗平面也随同一目标区域放大。最后一个门户帧，新画面的变换回到单位矩阵，下一帧直接接全幅，不再跳一次比例。

这次侧窗边界是四角近似，未精细描出弧形窗沿，也没有单独重建驾驶者、手指与后视镜的复杂遮挡。它是本轮最值得继续精修的位置。原参考的指缝与手指边缘变形更复杂，仍有差距。

实际验收时还修过一个透视问题：动画库直接处理 `transform` 时拆解了完整的投影矩阵，窗内画面因此被拉歪。最后用CSS自定义属性 `--portal-matrix` 保存逐帧矩阵，通过 `transform: var(--portal-matrix)` 应用，只重渲染受影响的50帧段。学这个例子时，要把“矩阵数据正确”和“浏览器最终按这个矩阵画出来”作为两件事检查。

## 五、其他实际做了什么

|处理|用途|边界|
|八片放射拼接并归位|把爆炸段做成短暂扩散的视觉节点|爆炸本身来自电影，新增的是画面分片与运动|
|局部尺度推拉、轻微转向和模糊|把视线从大场景引向动作细节|这是画面几何变化，不冒称真实镜头变焦或复杂光流变速|

|HDR转SDR、统一有效画面和黑边|让不同电影的素材能在一个项目里正确显示|未进行逐镜复杂电影级调色|

没有追加大字幕，因为V07画面重点在动作与遮挡。也没有把普通分屏当作这次的主要技法。

## 六、OpenChatCut和HyperFrames各做什么

OpenChatCut保存镜头剪辑与音乐；HyperFrames实际渲染组合动画。两个工程的总长度、帧率和素材位置对齐。

OpenChatCut中：

- **01 HyperFrames预览**：15段各2秒的已渲染插片，视觉与成片一致。可调整段落位置，段内透明边缘需要回HyperFrames修改。
- **02 原生镜头**：32个独立镜头、独立库内音乐。适合学习选镜、裁切与时间线；本身不包含HyperFrames的全部透视/动态alpha效果。

HyperFrames中：

- `edit.json`：片长、镜头时间、前景进入时间、背景切换时间和运动幅度。
- `composition.py`：把这些数据写成HTML/GSAP动画。
- `assets/alpha/*/roto-keyframes.json`：手工轮廓点。
- `motion/window-keyframes.json`：侧窗手工锚点。
- `motion/portal-matrices.json`：跟踪后的逐帧透视矩阵。

先复制工程再练习。建议第一次只改 `edit.json` 中 `effects` → `steering` 的 `x`，例如480改成300，观察手进入画面的距离；不要同时修改时间、旋转和遮罩，这样更容易看懂一个参数的作用。

## 七、本机实际命令流程

在HyperFrames工程文件夹打开PowerShell：

```powershell
$py = 'C:/Users/PC/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
$node = 'C:/Users/PC/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe'
& $py -X utf8 .\composition.py
& $node .\hf.mjs lint .
& $node .\hf.mjs preview . --port 5215 --no-open
```

第一条把编辑数据生成预览页面；`-X utf8`让中文路径和输出稳定。`lint`检查结构，不代表画面已经好看。`preview`打开本地编辑服务，然后在浏览器访问 `http://127.0.0.1:5215`。

本次lint为0错误、3警告：8片放射结构复用了同一媒体，以及逐帧透明图片使两个轨道比较密。重复媒体是有意的分片；透明PNG是实际运动遮罩。已保留这些提示，没有把“0错误”说成全部视觉验收。

生成器还会保护你在Studio里直接改过的HTML：再次生成前，将旧版本存入 `.source-backups`，扩展名为 `.html.bak`。本次发现把备份仍命名为 `.html` 放在工程根目录，会被Studio当作第二个作品，引出重复入口提示，已修正这个保存方式。

完整重新渲染：

```powershell
& $py -X utf8 .\tools\render.py --work .\.render-cache
```

脚本按50帧一组调用真实HyperFrames CLI，得到PNG序列，再用FFmpeg合成MP4并加入库内 `master.wav`。分组是为了限制内存，不会把成片分成多个文件。未变动的组会校验输入指纹后复用缓存。

其中一次底层命令的结构是：

```powershell
node hyperframes.mjs render <临时合成目录> --fps 25 --format png-sequence --workers 1 --low-memory-mode --sdr --experimental-fast-capture=false --no-best-effort --output <逐帧输出目录>
```

尖括号是说明占位，不要原样粘贴；上面的 `tools/render.py` 已自动填好这些路径。`--workers 1`限制并发，`--low-memory-mode`控制内存，`png-sequence`便于逐帧检查。预览用视频，离线渲染用对应源帧PNG，二者使用同一套图层和动画规则。

此电脑曾出现FFmpeg直接写文件失败，而向标准输出写二进制可用的情况。脚本用Python打开文件句柄，再让FFmpeg写 `fd:1`。不要用PowerShell文本重定向来保存图片或音频，也不需要关闭系统防护。

常见检查：

```powershell
& 'C:/Users/PC/Apps/ffmpeg/bin/ffprobe.exe' -v error -count_frames -show_streams -show_format -of json '..\越界_V07复刻.mp4'
```

需要看到750视频帧、25/1帧率、30秒长度、48kHz立体声音频。再看画面里的连续动作和实际播放情况；文件存在、编码成功和视觉合格是不同检查。
