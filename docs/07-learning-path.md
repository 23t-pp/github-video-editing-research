# 不会编程也能逐步学会看模板

## 第一轮：先知道自己要改什么

打开README里的候选表，先选一种任务：电影情绪混剪、照片卡点、产品动效、口播高光，或剪映可编辑草稿。它们的素材和输出不同，先不要同时安装全部项目。

“模板”可以理解为已经安排好的骨架：哪些镜头先出现、画面在哪、文字怎样动、音乐何时切。可复用模板还应有明确的替换入口。只有一段宣传视频或一个空白React项目，不能满足“换素材复用”。

## 第二轮：只读四个位置

1. README：作者说它适合什么，演示的是哪一种输入和输出。
2. LICENSE：源代码的许可；媒体、字体、Remotion等依赖可能有独立条款。
3. 配置示例：photos、clips、text、music、fps、duration等字段在哪里改。
4. render入口：修改配置以后，哪条命令实际把它变成视频。

可以把仓库链接交给助手，并使用下面的明确请求：

> 请先只读检查这个仓库。告诉我素材放哪里、改哪个配置、预览和导出分别用什么命令、哪些依赖会联网或收费。用一个最小样例说明，不要默认所有模板都支持自动卡点。

## 第三轮：按三条学习路线选择

| 路线 | 入门 | 进阶 | 你会学到什么 |
|---|---|---|---|
| 音乐混剪 | beat-synced-edit的beat_map→plan_edit→render_edit | easyedit的节拍槽位与film.js | 声音时间如何变成剪切时间，剪辑逻辑与视觉模板如何拆开 |
| 纯模板 | Opus30的25号六图模板；已有Herk starter | 官方HyperFrames launches、已有video-shotcraft | 如何保留动效结构，只替换图文与品牌；固定时间线怎样调音乐 |
| AI剪辑 | FunClip的文字定位、auto-editor的静音删除 | OpenChatCut / agentic-video-editor | 语音转写、规则剪辑、视觉模型选镜分别解决什么问题 |

VVV和slideshow适合照片路线；VVV的完整验证环境偏macOS，Windows需要先核依赖。不要把“代码看起来跨平台”当作“已经在Windows跑通”。

## 第四轮：学会验收一个20秒或30秒样例

第一次只用少量自己拥有的素材，先预览再渲染。检查：总秒数和帧数是否一致、有没有空白/黑帧、镜头是否重复、文字是否可读、音乐切点是否准确、换一个素材后能否再次生成。

先以本仓库的只读命令练习：

```powershell
gh repo view blixvip/easyedit
gh api repos/blixvip/easyedit --jq '{name:.full_name,branch:.default_branch,license:.license.spdx_id}'
```

下一步才考虑下载源码；下载不等于安装，也不等于执行：

```powershell
# 后续学习示例：在你选定的练习目录内运行
gh repo clone blixvip/easyedit
```

本次没有替你执行这个剪辑项目的安装命令。每个仓库的依赖版本不同，应读所选固定版本的README后再安装。

## 常见术语速查

| 词 | 白话解释 |
|---|---|
| beat / 拍点 | 音乐的节奏时刻，不一定每个鼓点都算一拍 |
| onset / 起音 | 声音突然出现或增强的位置 |
| BPM | 每分钟多少拍；知道BPM仍需要起拍位置 |
| beat grid | 一组按拍排列的时刻，可能实测也可能规则生成 |
| EDL | 剪辑决定清单，记录取哪个素材的哪一段 |
| OTIO / FCPXML | 可用于在剪辑工具间交换时间线的格式，兼容性需实测 |
| fps | 每秒多少帧 |
| render / 渲染 | 把时间线、画面、声音计算并编码成文件 |
| ASR / Whisper | 把人声转成文字的一类工具；有转写不等于会判断精彩片段 |
| VLM / 视觉模型 | 可以分析图像或视频内容的模型；费用与效果需按实际输入测试 |
| fallback | 主方案不满足条件时采用的回退方案；例如没检测到拍点就用120 BPM |
| mock | 模拟数据；不能把它当作真实分析结果 |
| props / config | 模板接受的参数，例如图片、标题、颜色、时长 |
| fork / mirror | 分叉副本／同步镜像；不应重复当成独立原创项目计数 |
| static review | 只看代码和文档，未把软件实际运行起来 |

每看懂一个字段，就追踪它怎样进入渲染。这个习惯比记住更多仓库名字更有用。
