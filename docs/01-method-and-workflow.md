# 检索、审查与动态分工的方法

本报告把“AI 剪辑、纯剪辑、卡点混剪、模板”视为重叠但不同的需求。输出是可检查的研究记录：问题、操作、证据、结论、限制。每个推荐都应能追溯到仓库和文件。

## 需求与研究范围

用户选择三类全覆盖：

1. 音乐卡点、情绪混剪、歌词 MV。
2. 对已有素材进行 AI 理解、选段、剪辑。
3. 替换照片、视频、文字、音乐后可复用的时间线或动效模板。

当前聊天的工作目录初始没有项目代码。后续用户另一窗口提供了本机项目的只读核验交接，主流程进一步复核关键源码与两个成片的媒体元数据，因此另外形成了[当前项目洞察](06-current-project-insights.md)。本机项目证据采用脱敏观察记录，与公开GitHub源码证据分开；未上传原工程或素材，也未宣称完整观看验收。

## 为什么这样扩展关键词

中文“剪辑”可能指删除静音、挑高光、自动组装、加字幕、按音乐切镜，也可能只是生成新画面。每一种任务需要不同实现。

| 用户表达 | 查询扩展方向 | 容易混入的结果 |
|---|---|---|
| 卡点混剪 | beat sync、beat-synced、AMV generator、montage | 音频可视化、只按固定 BPM 播动画 |
| AI 剪辑 | AI video editor、video highlight、video clipping、LLM、Whisper | 文案加配音、库存素材合成、纯文生视频 |
| 剪辑模板 | Remotion template、HyperFrames template、slideshow、Shotstack template、剪映草稿 | 空白脚手架、模板导航站、只提供 SDK 的仓库 |
| 歌词 MV | lyric video、music video generator | 只生成歌词、只有频谱、不切真实镜头 |

GitHub 原生仓库搜索主要匹配文本；本次“语义搜索”的实际含义是人工扩展同义词、邻近任务和品牌种子，再按代码证据筛选。没有声称调用了 embedding 数据库或 GitHub 的向量搜索接口。

首轮每条查询取最多 30 条，没有逐页抓完所有结果。部分宽泛查询用最低星数控制噪声；卡点和具体模板查询保留了低星项目。补种子、读相关项目链接，可以减少只按关键词造成的漏检，但不能证明全网穷尽。

## 代理分工与调整

按用户指定，主流程使用 GPT-6 Astra；三个子代理使用 GPT-6.1 Sol，high 推理配置。

| 角色 | 工作范围 | 汇总时的重点 |
|---|---|---|
| 主流程 | 范围拆分、CLI登录验证、跨类别补漏、本机已有能力、整合去重、中文文档与发布 | 推荐是否重复、数字是否可追溯、证据是否支持结论 |
| 卡点代理 | 节拍检测、EDL、音乐切镜、AMV、白闪模板 | 真检测与固定时序的区别 |
| 模板代理 | Remotion、HyperFrames、剪映草稿、云渲染模板 | 是否有实际模板、素材参数、导出路径 |
| AI代理 | 高光、语义选段、字幕、素材理解 | 是否剪用户素材、API依赖、能否回编辑器继续修改 |

动态调整发生在实际发现之后：

- 主流程找到官方 HyperFrames launch 项目、已有的 Herk / video-shotcraft 后，通知模板代理补查及去重。
- 发现 `easyedit` 同时有节拍与 HTML 模板，将它加入卡点源码审查，而非仅按初始关键词名单结束。
- AI代理发现 OpenChatCut 有节奏分析和时间线实现，提升为三类交叉候选。
- 发现许可证、模拟节拍回退、静态模板、Windows导入障碍等证据后，修改原始推荐级别。
- 用户增加公开仓库与教学要求后，扩展了源码审查深度、命令教程与证据归档。

这是一套按证据调整范围的分工；没有为本次一次性调研另外安装“多代理框架”。

## 证据等级

| 等级 | 实际做过什么 | 可以支持什么 |
|---|---|---|
| E0：检索命中 | 保存公开搜索元数据 | 项目出现在某条查询结果里 |
| E1：文档核查 | 看README、依赖、LICENSE、目录 | 作者声明、复用入口、安装要求 |
| E2：静态源码核查 | 找到输入、算法、调用关系、输出文件 | 代码确实实现了某个逻辑，或有明确限制 |
| E3：运行验证 | 在确定环境和素材上执行并检查输出 | 这组条件下是否能跑通、效果如何 |

本次重点项目达到 E1/E2；候选剪辑项目没有做 E3。调研脚本的解析与数据校验、GitHub发布核验属于研究交付本身的验证，不会被算成剪辑产品的运行测试。

## 判断标准

优先考虑：任务匹配 → 是否存在实际模板或剪辑实现 → 许可与运行门槛 → 可编辑性 → 维护情况。星数只作背景，不作为“好看”“成熟”“生产可用”的证明。

对节拍能力单独标记：真实音频检测、给定 BPM 网格、手写时间点、仅音乐可视化、未找到证据。项目同时具备几种能力时按模块说明，不能用一个标签覆盖所有模板。

对素材输入单独标记：用户自己的本地素材、公开视频或在线素材、AI生成画面、纯HTML/图形。对输出单独标记：仅MP4、EDL/OTIO/FCPXML、HTML/React工程、剪映草稿。可编辑性直接影响你以后修改的成本。

## 去重口径

同一 GitHub 数字 id 是身份重复；官方同步镜像属于来源重复；模板引用上游属于模板级重复；两个独立实现同一功能只算功能重叠。四者不会混为一谈。

默认仓库搜索未额外加入 `fork:true`，所以不能宣传“已经完整审查了所有fork”。搜索池中的身份去重数字可由脚本复算；模板族归并单独记录证据，不拿它去随意减少身份统计。

## 何时停止搜索

三类目标都有直接候选，已有代表项目和实际模板的源码证据，主要复用限制已标注，新增候选主要带来重复或外围能力时，进入综合交付。没有把“再搜一次可能有新项目”当作无限扩展任务的理由。

仍待实际项目阶段验证的事项包括：素材质量、节拍误差、长片耗时、Windows原生依赖、GPU占用、导出观感，以及你偏好的美术风格。
