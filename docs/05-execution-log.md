# 执行与复核记录

本日志解释本次实际做过的操作及处理过程。它与[可复制CLI教程](02-cli-guide.md)互补：教程解释通用命令，这里说明本次发生了什么。

## 1. 确认需求和工具

用户要求三类都查：音乐卡点混剪、AI剪已有素材、可换素材模板；后续明确要求建立public GitHub仓库，README主要中文、详细到适合零基础学习。

读取了skillzhushou检索技能与AI标杆参考。按用户指定使用gh，替代技能默认的免登录Python搜索脚本。主流程确认gh 2.103.3及账号登录可用；当前应用PATH没有gh短命令，使用标准安装目录的完整路径调用。

## 2. 并行检索，保存原始结果

主流程4条、音乐8条、模板8条、AI8条，共28条repo查询。三名子代理按用户指定的GPT-6.1 Sol high运行；主流程为GPT-6 Astra。

实际命令的结构为：

```powershell
gh api --method GET search/repositories -f 'q="beat-synced"' -f per_page=30
```

所有查询、数量和原始JSON逐条列在[查询日志](09-query-log.md)。首轮共598条记录，按数字id为555个仓库。宽泛中文查询带来游戏、健康打卡等噪声；加入英文术语与品牌/相关项目补漏后再选重点。

## 3. 逐个锁定版本并核查

每个重点项目读取metadata，查default_branch，获取该分支commit SHA，再以同一SHA读tree、README、LICENSE、依赖和关键文件。目录树若截断必须补查；不能把仅存在文件名当成实现已确认。

主要纠正包括：白闪模块按配置而非自动卡点；模拟120 BPM回退；高星视频生成与真实素材剪辑的差别；受限许可证；Windows的fcntl导入障碍；某些“动效模板”实际为静态样式。详见[完整审查目录](03-reviewed-catalog.md)。

读取官方launch子项目时，直接尝试父目录下index.html和hyperframes.json得到404。查看tree后确认文件位于`heygen-apple-motion/01-ui-sting/`等目录，改为实际路径继续。这是路径纠正，没有将404解释成仓库不存在。

## 4. 本机已有能力与项目复核

初始聊天目录没有业务源码，但另一窗口随后提供真实工作区的只读核验。主流程复读三个关键构建/质检文件，并对两个现有成片运行ffprobe。

公开报告只保留脱敏统计和观察：20秒项目479帧／24fps；60.7秒项目3642帧／60fps，与208镜头的frames合计一致；变速字段未进入某构建函数；质检抽帧把秒再次除以60。没有修原项目，没有把媒体元数据等同全片视听验收。

已有Herk提交与上游一致，video-shotcraft安装清单也与本次上游快照一致，因此归为已有能力。dsh-montage同版本副本仍有Windows适配差异，不能按version字符串认定逐文件相同。

## 5. 交叉复核发现并修正

卡点代理完成首轮后，再只读检查主流程教程/脚本与模板报告，发现了两个具体问题：

1. 复跑搜索后的Merge默认指向历史数据，且若直接指向新目录会误读queries.json。已修改Search把原始响应放到`run/raw/`、返回目录对象；教程显式把这个目录传给Merge。
2. 分支报告带本机绝对路径。发布版统一转成相对证据路径或脱敏说明。

交叉复核还补读VVV的音乐分析脚本，确认存在FFmpeg解码、谱通量、自相关tempo与DP节拍生成。措辞改为“音轨检测生成的beat map（本次未运行）”，避免“实测”让人误解为本轮跑过音乐。

## 6. 数据组装与异常处理

用本地Node读取各分支JSON、统一字段、按GitHub数字id合并，再生成目录与证据文件。当前环境Node写输出文件遇到EPERM；改由Node经标准输出交出生成内容，PowerShell在已确定的交付目录写文件。文件目标先检查处于交付目录内，没有扩大权限或改系统配置。

组装后为557个仓库身份：555个搜索身份，加2个指定仓库探查新增身份。26项重点静态源码审查，115条固定提交证据，27项明确排除/降级理由。模板族去重与身份统计分开保存。

上游整套README/源码只在研究工作目录读取，没有原样复制进这个公开仓库。公开的是原创审查总结、元数据和来源链接。
