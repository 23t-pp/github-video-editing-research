## 还原工程

1. 将对应 `*-complete.zip` 解压到一个新的工作区根目录。包内保持 `outputs/项目名/...`，可以合并多个项目。
2. 查看包根的 `PUBLICATION-ASSET-RESTORE.json`。现有 `HyperFrames可编辑工程.zip` 作为独立 release 资产保存一次；按 `restore_path` 把下载资产复制回原文件名。S1 的原生 `.ccproj` 也作为独立资产，依同一清单放回。
3. 合并解压 `publication-supplement.zip`，补齐已实检的非秘密素材指纹、侧脸及OCC命令日志；`restore_projects.py`会自动处理。再解压 `execution-and-research-sources.zip` 到同一根目录，得到 `work/...` 的自写执行源码与调研快照。运行工具依赖需按原项目说明安装；不要将本机 profile、token 或 .env 放入公开目录。
4. 完整 S1 JPG 库由另一个 JPG release 提供。其分卷需还原至 `outputs/jjk-s1-workflow/素材集_60Hz_JPG`，按 JPG 总清单核验。工程包不重复存储 2,061,018 条 JPG 路径。
5. OpenChatCut 打开对应 `.ccproj`；HyperFrames 解压对应可编辑工程 ZIP，并按项目内 README 操作。源码中的绝对素材路径是原制作环境的证据；复现取片时应映射到自己的合法原片位置。

## 核验方式

`assets-manifest.json` 列出每个 release 资产的字节数和 SHA256；`manifests/*.zip.json` 列出完整包每个源文件的原路径、字节数、SHA256 与 CRC32。制作压缩包时读取源字节计算摘要，再重新解压读取所有 entry，比对字节数、SHA256、CRC32，同时核对 ZIP CRC。独立已有 ZIP 复制后进行源/副本 SHA256 比较及内层 ZIP CRC 检查。

`text-staging` 是用于 Git 浏览的小文本镜像，不是完整媒体包。其逐文件来源和 SHA256 在 `manifests/text-mirror-manifest.json`。大型媒体、音频和工程数据依 release 资产获取；公开仓库不依赖把大媒体硬塞进 Git。
